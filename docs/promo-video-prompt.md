## 主提示词（整段复制）

```text
帮我做一支产品宣传视频，用于发布一个 DeepSeek Harness 插件。请先读完再动手，成品是一个真实的 mp4 文件。

## 产品事实（不要编造，只用这些）

品牌：DevDock（套件的品牌名）
当前模块：GitHub / Git（npm 包名 dsh-harness-push，这是已公开发布的版本）
定位：在 DeepSeek Harness（一个开发者用的 AI 客户端）里管理研发账号与服务，不用在浏览器标签和终端之间来回切换。
套件的规划：先做 GitHub/Git，后续接入 Cloudflare（Workers / Pages）与 npm。对外只有一个入口、一套操作习惯，平台在入口内部用下拉切换，平台越多占用空间不增加。

可以强调的真实亮点（每条都真的存在，不要说成别的）：
1. 多账号：账号卡片显示头像、昵称、权限范围，下拉即切，所有面板立刻跟随，不用重启。
2. 凭据安全：推送令牌通过子进程环境变量注入，不写进 .git/config，也不出现在命令行里；界面上其它账号看不到令牌原文。
3. 推送前 Agent 审查：推送前先跑规则扫描（免费、必定执行，抓令牌/私钥/本机路径等），再可选地让模型按你勾选的审查项看一遍。发现阻断级问题时只警告、不阻止推送。
4. 推送记忆：每条 git 分支记住上次推送到哪个仓库、哪个 ref，下次回到该分支自动带出。
5. 版本树：提交图带 lane 连线与 ref 标签，任意节点可检出、反向提交、打标签。
6. 人和 AI 同源：同一套能力同时暴露成模型工具 github_link，界面上的操作和智能体调用的行为完全一致。

## 成品规格

- 1920x1080，16:9，30fps，H.264（yuv420p），无音轨
- 时长 30 到 60 秒之间，建议 45 秒左右
- 中文文案，界面里的英文（GitHub、npm、Cloudflare）保留原文
- 输出到工作区：promo/devdock-promo.mp4

## 视觉风格：克制的编辑感（参考 Claude / Anthropic 的产品视频气质）

不要做那种满屏渐变、3D 弹跳、粒子爆炸的科技感宣传片。要像一本排版讲究的杂志翻页：

- 背景：暖白 #F5F4EE，或深炭 #191919，二选一，全片统一
- 正文与标题：深炭 #191919（深色底时用 #F5F4EE）
- 强调色：只用一种，赤陶橙 #D97757，只用来点出关键词或一个短横线
- 辅助色：石灰 #B8B2A7，用于分隔线、注释小字
- 排版：大量留白，内容集中在画面中间约 60% 的区域；左对齐为主，不要居中对齐到随意的位置
- 字：中文用「微软雅黑 Bold」（C:/Windows/Fonts/msyhbd.ttc），英文数字用 Georgia 或 Times New Roman 做标题衬线感；小标签用全大写 + 字间距放宽
- 动效：只用淡入淡出、缓慢位移（6~14px）、不透明度渐变、细线生长。禁止缩放冲击、禁止抖动、禁止弹跳
- 转场：硬切或 300ms 交叉淡化，不要花哨转场
- 每个画面停留至少 2.5 秒，让观众看清楚
- 不要 emoji，不要感叹号，不要「震撼」「颠覆」这类营销词

## 分镜结构（可以微调，但要覆盖全部亮点）

1) 0–4s 开场：全屏暖白，一行大字定位。例如「研发账号与服务，一个面板管完」。右下角小标签：DevDock
2) 4–12s 痛点：三行短句依次淡入，每行一句。例如「切仓库要开浏览器」「令牌散落在配置文件里」「推送前没人再看一眼」
3) 12–22s 亮点一（多账号切换）：放一张真实界面截图，配一圈极细的强调色描边和一句说明「多个 GitHub 账号，下拉即切」
4) 22–32s 亮点二（推送前审查）：截图 + 说明「推送前先过一遍：规则扫描必跑，模型审查可选」
5) 32–40s 亮点三（版本树 / 推送记忆）：截图或提交图特写 + 说明「每条分支记住上次推到哪」
6) 40–48s 人机同源：一句话 + 极简示意，例如「同一个能力，界面和智能体都能用」
7) 48–56s 收尾：品牌 + 安装命令 dsh plugin --profile desktop add dsh-harness-push，下面一行小字「DevDock 套件 · 后续接入 Cloudflare 与 npm」

## 素材：真实截图怎么来

优先用真实界面截图，但**不要伪造截图，也不要假装你截了图**：

- 如果工作区里已经有截图（promo/shots/ 下的 png/jpg），直接用
- 如果没有，先检查有没有可用的截图能力（浏览器控制、录屏工具）。没有就明确告诉我，并向我要截图；同时可以先做一版不含截图的纯排版版本，保证按时能交
- 如果确实要用合成画面代替截图，必须做减法：只用色块、细线、圆点和真实文案搭出「界面感」，不要画假的按钮细节，避免看起来像赝品

建议向我要这些截图（1080p 以上，裁掉无关部分）：
1. 设置页的 Push 一页（能看到账号卡片）
2. 左侧栏仓库面板的卡片视图（能看到语言占比条）
3. 工作区侧边栏的推送面板（能看到改动列表和推送按钮）
4. 审查弹窗（能看到审查项卡片）

## 技术实现

环境已确认可用：
- ffmpeg 在 C:\ffmpeg-8.0.1-essentials_build\bin\ffmpeg.exe
- Python 3.10，已装 Pillow、numpy、moviepy
- 中文字体：C:/Windows/Fonts/msyhbd.ttc（粗体）、msyh.ttc、simhei.ttf

推荐做法（稳）：用 Pillow 按帧渲染 PNG 到临时目录（每个画面按 30fps 展开，或渲染关键帧后用 ffmpeg 做淡入淡出），再用 ffmpeg 合成 mp4。moviepy 也可，但注意它的中文字体渲染有时需要显式指定字体文件。

字幕：中文直接烧进画面（不要做成需要播放器支持的字幕轨）。

## 验收（必须做，不要只报"渲染成功"）

1. ffprobe 检查：时长在 30–60s 之间、1920x1080、30fps、h264、无音轨
2. 用 ffmpeg 抽 4 帧（开头、两个亮点、结尾）保存成 png，然后用读图工具逐张看一遍，确认：文字没被裁掉、没有重叠、强调色只用了一种、没有乱码方块
3. 把检查结果和那 4 张图一起发给我
4. 如果发现问题，改完重新渲染，再验一次
```
